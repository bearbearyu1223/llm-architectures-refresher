1. Where the parameters actually are               [post §1]
--------------------------------------------------------------------------
  role          parameters   share
  ----------------------------------
  experts           6.442B   93.1%
  attention         0.269B    3.9%
  embed + head      0.206B    3.0%
  router             2.10M  0.030%
  norms              0.07M  0.001%
  TOTAL             6.919B  100.0%

  experts per layer                  64
  experts used per token             8
  parameters in one expert           6.29M
  total parameters                   6.919B
  active parameters per token        1.177B
  active share                       17.0%

  >> 93% of the weights are experts, and a token touches 8 of 64 of them.
     The model is mostly a thing it declines to use.

  Why 64 experts and 8 per token, rather than 8 and 2?

  model width (hidden_size)          2048
  one expert's width                 1024
    as a multiple of the model width 0.50x
  width actually used per token (8 x 1024) 8192
    as a multiple of the model width 4.00x
  width held in total (64 x 1024)    65536
    as a multiple of the model width 32.00x
  capacity over compute              8x

  A dense FFN is conventionally 4x the model width. Per token this
  model does exactly that much FFN arithmetic -- while holding 8x it.

  Same total width, same width used per token, split four ways:

  experts  each of width  used per token  possible combinations
  ---------------------------------------------------------------
  8                 8192               1                      8
  16                4096               2                    120
  32                2048               4                 35,960
  64                1024               8          4,426,165,368

  >> Every row costs the same to store and the same to run. Splitting the
     same budget into 64 pieces instead of 8 turns 8 possible expert
     combinations into 4,426,165,368, which is what the count is really
     buying.

  Total variation distance between expert-usage distributions:
  0.00 = the two samples used the experts identically.

  comparison           layer 0  layer 8  layer 15   mean
  --------------------------------------------------------
  same passage, split    0.240    0.210     0.173  0.216
  prose vs code          0.465    0.736     0.855  0.731

  most code-leaning expert (layer 15) 17

    share of prose routing slots     0.13%

  experts unused by prose but used by code 13

  noise floor, first layer           0.240
  cross-domain, first layer          0.400
  noise floor, last layer            0.173

  >> Two halves of one passage differ by 0.22; two different kinds of text
     differ by 0.55, 2.6x as much. Expert choice tracks the kind of text,
     and the gap widens with depth.

5. Two bills: memory and time                      [post §5]
--------------------------------------------------------------------------
  weights resident (bf16)            12.89 GiB
    every expert must be in memory; the router picks at run time,
    so there is no subset you could have left on disk.

  experts per token  forward (ms)  vs top-8
  -------------------------------------------
  8                         429.1     1.00x
  64                        928.7     2.16x

  expert FLOPs ratio (64/8)          8x
  measured wall-clock ratio          2.16x
    below 8x because attention, norms and the LM head are unchanged

  >> Turning every expert on costs 2.2x the time and 0 extra bytes of
     weights. Memory is billed on 6.9B parameters no matter which 8 get
     used.

6. Sparsity does not survive a batch               [post §6]
--------------------------------------------------------------------------
  passage                            356 tokens

  tokens together  experts needed  of 64  expert-slots used
  -----------------------------------------------------------
  1                           8.0    12%                  8
  2                          13.1    20%                 16
  4                          21.1    33%                 32
  8                          31.4    49%                 64
  16                         40.8    64%                128
  32                         48.5    76%                256
  64                         53.9    84%                512
  128                        58.0    91%               1024
  256                        60.9    95%               2048

  >> One token needs 8 experts; 256 tokens together need 61. Sparsity is a
     property of a token, not of a batch — which is why an MoE saves
     arithmetic but not memory.

7. Experts across GPUs                             [post §7]
--------------------------------------------------------------------------
  passage                            356 tokens

  GPUs  experts each  GPUs per token  of all  tokens needing all
  ----------------------------------------------------------------
  2               32            1.99    100%                 99%
  4               16            3.67     92%                 68%
  8                8            5.54     69%                  0%
  16               4            6.84     43%                  0%

  >> Split across 8 GPUs, one token's 8 experts land on 5.5 of them on
     average. Expert parallelism moves tokens between GPUs, and the router
     decides how much.

8. Nothing balances the load for free              [post §8]
--------------------------------------------------------------------------
  passage                            356 tokens
  routing slots per layer            2848

  layer  busiest  quietest  busiest vs even  coeff of var
  ---------------------------------------------------------
  0        8.92%     0.04%            5.71x          0.88
  8        7.30%     0.00%            4.67x          0.89
  15       8.32%     0.00%            5.33x          1.07

  even share would be                1.56%
  router_aux_loss_coef               0.0100
  experts never used (last layer)    4

  >> Nothing makes the experts equally popular by construction; a balance
     penalty during training is what keeps one expert from swallowing the
     traffic and the rest from starving.
